💊 Project Background

People choosing a drug usually see only a star rating. This project brings reviews, ratings and price together so drugs can be compared properly.

  • Source: Drug.csv, hosted in a GitHub repository
  • Ratings: Effectiveness, ease of use and satisfaction from customer reviews
  • Extra context: Drug type, form, indication and average price

🎯 Project Objective

  • Review Volume: Finding which conditions get the most reviews
  • Rating Comparison: Comparing OTC, RX and RX/OTC drugs
  • Price Analysis: Understanding price by drug form
  • Value for Money: Spotting drugs with strong ratings at a low price
  • Fair Ranking: Weighting ratings by number of reviews

🧮 Key DAX Measures

Each rating is multiplied by its number of reviews before averaging, so a drug with 3,000 reviews counts for more than one with 3.

Weighted Satisfaction =
DIVIDE(
    SUMX(Drug, Drug[Satisfaction] * Drug[Reviews]),
    SUM(Drug[Reviews])
)

Overall Value Score =
DIVIDE(
    ([Weighted Effective] + [Weighted EaseOfUse] + [Weighted Satisfaction]) / 3,
    [Avg Price]
)

Satisfaction Level =
VAR s = [Weighted Satisfaction]
RETURN
SWITCH(
    TRUE(),
    ISBLANK(s), BLANK(),
    s < 1, "Very Unsatisfied",
    s < 2, "Unsatisfied",
    s < 3, "Partly Satisfied",
    s < 4, "More Than Satisfied",
    s <= 5, "Very Satisfied"
)

🚀 Key Learnings

1
Weight ratings by reviews A plain average treats a drug with 3 reviews like one with 3,000, which can mislead.
2
Set a minimum review count Filtering out drugs with very few reviews keeps rankings and scatter charts reliable.
3
Clean blanks before visuals Replacing empty values with "Unknown" avoids confusing "(Blank)" labels in slicers and charts.
4
Treat value scores as a guide Value Score helps explore the data, but it says nothing about which drug is right for a person.
